# OTA 升级自动化压测

> 面向 Windows 平板的 **BIOS / 控制中心（SystemControl）OTA 升级**自动化循环压测脚本。
> 通过"读版本 → 图像识别定位升级入口 → 自动执行升级 → 版本比对 → 静默回退 → 再升级"的闭环，实现**无人值守反复升级压测**，用于验证 OTA 升级的稳定性与"防批量变砖"。

---

## 1. 背景

OTA 升级是平板产品的高风险功能：一次升级流程涉及固件写入、重启、版本切换，任何一步异常都可能导致设备变砖。要验证升级的稳定性，需要**反复升级成百上千次**并每次校验结果——纯手工不可行。

本项目用两支脚本把 BIOS 和控制中心两类 OTA 升级流程完全自动化，可 7×24 无人值守循环压测，每轮自动比对版本号确认升级/回退是否成功。

## 2. 脚本说明

| 文件 | 功能 |
|------|------|
| `bios_update.py` | **BIOS OTA 升级压测**。通过 WMI 读取 BIOS 版本（`V500R001B01xxx`），OpenCV 图像识别定位控制中心升级入口，pyautogui 自动执行升级；升级后版本比对，再静默安装旧版本回退，如此循环。 |
| `ota_update.py` | **控制中心（SystemControl）OTA 升级压测**。通过注册表读取应用版本，OpenCV 模板匹配判断控制中心是否打开，自动点击升级；`success ↔ 旧版本` 之间循环（静默卸载 + 静默安装旧版本），统计成功次数。 |
| `脚本说明.txt` | 原始脚本说明 |
| `*.jpg` | OpenCV 模板匹配用的界面基准图（控制中心 / 升级按钮） |

> 打包产物 `bios_update.exe`、`ota_update.exe`、升级包 `D020.exe`、`SystemControl_*.exe` 等大文件未入库。

## 3. 核心设计

1. **版本客观比对**：
   - BIOS 版本来自 `wmi.WMI().Win32_BIOS()[0].SMBIOSBIOSVersion`，正则提取；
   - 应用版本来自注册表 `Uninstall` 项的 `DisplayVersion`。
   - 每轮升级后强制比对 `旧版本 / 新版本`，杜绝"以为升级成功了实际没成功"。
2. **图像识别定位入口**：升级按钮位置在不同机型/分辨率可能漂移，用 `cv2.matchTemplate`（相似度阈值 0.8）确认界面状态，并用轮询坐标点击兜底。
3. **重启后自动续跑**（`bios_update.py` 亮点）：BIOS 升级需要重启，脚本在启动时通过 `Schedule.Service`（Windows 任务计划）注册一个**登录后延时 30s 自启**的任务，机器重启后自动继续压测流程，实现真正的无人值守。
4. **管理员权限自举**：升级、注册任务计划、模拟键鼠均需管理员权限，非管理员启动时 `ShellExecuteW runas` 提权重启自身。
5. **升级 ↔ 回退闭环**：升到新版本后自动静默安装/卸载回退到旧版本，让"升级"这一动作能被无限次重复压测。

## 4. 技术栈

`Python 3` · `wmi` / `winreg`（版本读取）· `OpenCV`（模板匹配）· `pyautogui`（界面自动化）· `win32com`（任务计划注册）· `subprocess`（静默安装/卸载）· `PyInstaller`（打包）

## 5. 使用说明

> ⚠️ 依赖真实被测机、对应机型的升级包（`*.exe`）与界面基准图，且屏幕坐标为特定分辨率下标定，直接跨机运行需重新标定。以下为使用方式说明。

1. 在脚本开头修改 `old_version` / `new_version` 为你的目标版本号。
2. 将对应的升级包 exe、旧版本安装包放到脚本同目录。
3. 以**管理员权限**运行脚本，脚本会自动注册重启续跑任务并开始循环压测，控制台打印每轮升级结果与累计成功次数。
