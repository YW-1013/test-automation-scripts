# AudioTest · 分布式音频自动化测试框架

> 面向平板 / 大屏（Windows + Android 双系统）产品的**软硬件结合**自动化压测框架。
> client / server 双端 socket 分布式架构，以**音频频谱能量客观判声**为核心，覆盖上下电、双系统切换、扬声器 / 麦克风 / 相机 / U 盘 / 蓝牙 / 光感等多项硬件检测，可无人值守长时间循环压测。

---

## 1. 项目背景

平板 / 大屏产品在**反复上下电、双系统切换、休眠唤醒**等场景下，容易出现"扬声器无声、麦克风失效、相机黑屏、驱动丢失、桌面组件丢失"等硬件相关问题。这类问题**靠人耳/人眼长时间盯测既不可靠也无法回归**。

本框架把"设备是否正常"的判断**全部客观化、可量化**：
- **声音**：录制音频 → `scipy.fft` 做频谱分析 → 用能量 RMS 阈值判断"有没有正常出声"，而不是靠人耳听；
- **画面 / 相机 / 黑屏**：OpenCV 图像识别 + YOLO 模型辅助判断界面状态；
- **驱动 / 组件**：读取设备管理器异常状态码、检查桌面应用与小组件是否丢失。

配合物理上下电手段（模拟器 / 智能插座 / 机器人 / 串口），实现**无人值守的循环压测 + 异常自动记录 + 飞书结果推送**。

## 2. 架构设计

采用 **client（被测机）/ server（控制机）双端 socket 分布式** 架构：

```
┌─────────────────────┐         socket 通信          ┌─────────────────────┐
│   Server 控制端      │  ←──  握手 / 命令码 / ACK  ──→ │   Client 被测端      │
│  （tkinter GUI）     │                               │  （被测平板/大屏）   │
├─────────────────────┤                               ├─────────────────────┤
│ · 测试流程编排        │                               │ · 接收切换/检测命令   │
│ · 上下电 / 切换控制    │                               │ · 本机录音/截图/驱动  │
│ · 音频录制 + 频谱判声  │                               │   自检并回传结果      │
│ · 结果统计 + 飞书推送  │                               │ · 双系统切换执行      │
└─────────────────────┘                               └─────────────────────┘
```

- **命令码协议**：双端通过自定义数字命令码 + ACK 码握手同步（如「码 6 / ACK 62」触发快速切换），server 端设置连接超时并对半开/失效连接做兜底重连，避免卡死。
- **可中断等待**：核心循环用 `interruptible_sleep`（每 0.5s 检查运行/暂停标志）替代阻塞 `time.sleep`，保证"停止/暂停"信号能即时响应。
- **管理员权限自举**：涉及 `powercfg`、任务计划、模拟键鼠、杀进程等操作需管理员权限，非管理员启动时自动弹 UAC 提权重启自身。

## 4. 核心能力

| 能力 | 实现方式 |
|------|----------|
| **扬声器检测** | 录制播放音频 → `pyaudio` 采集 → `scipy.fft` 频谱能量 RMS 与阈值比对，判断是否正常出声 |
| **麦克风检测** | 采集麦克风输入，用同样的能量阈值判断收音是否正常（含 `+monkey` 混合场景） |
| **相机检测** | `pygrabber` 枚举摄像头 + OpenCV 抓帧，检测前/后/外接摄像头画面是否正常 |
| **黑屏检测** | OpenCV 图像识别 + YOLO 模型辅助判断界面状态 |
| **驱动检测** | 读取设备管理器，检查是否存在异常状态码的设备（通用模式，不依赖预设列表） |
| **U 盘 / 蓝牙 / 光感 / 充电检测** | 按设备名/连接状态校验外设识别是否正常 |
| **桌面组件检测** | 重启/开关机后检查桌面应用与小组件是否丢失 |
| **双系统切换** | 重启切换 / 休眠切换 / 快速切换（走 SystemControl WebSocket IPC 直连下发，失败自动回退点击控制中心） |
| **上下电控制** | 支持模拟器 / 智能插座 / 机器人 / 串口等多种物理上下电方式 |
| **结果推送** | 记录错误次数并生成日志；通过飞书机器人 webhook 推送测试结果 |

## 5. 技术栈

`Python 3` · `socket`（分布式通信）· `tkinter`（GUI）· `OpenCV` + `YOLO`（图像/界面识别）· `scipy.fft` + `numpy`（频谱判声）· `pyaudio` / `wave`（录音）· `uiautomator2` + `adb`（安卓自控）· `pywifi`（WiFi 配置）· `pygrabber`（摄像头枚举）· `wmi` / `winreg` / `pyautogui` / `win32com`（Windows 自控）· `PyInstaller`（打包为带 GUI 的 exe 供团队使用）

## 6. 快速开始

> ⚠️ 本框架为**内网真机压测工具**，依赖 ffmpeg、YOLO 模型权重、adb、真实被测设备等本地环境，直接开箱即跑需自行补齐这些依赖与配置。以下为使用方式说明。

1. **准备环境**
   ```bash
   pip install -r edp-large-screen/server/requirements.txt
   # 另需自行准备：ffmpeg.exe、YOLO 模型（*.pt）、adb 工具、被测设备
   ```
2. **准备配置**：复制对应目录下的 `config*.example.json`（或 `audio_test.ini`）为真实配置，填入你的 `device_ip / host_ip`、相似度阈值、音频 RMS 阈值、外设名称等参数。
3. **启动**（均需**管理员权限**）：
   - 被测机运行 `client` 端程序；
   - 控制机运行 `server` 端程序，在 GUI 中勾选测试项、选择切换方式与上下电方式，开始压测。

## 7. 配置项说明（示例）

`config.example.json` 中的关键字段：

| 字段 | 含义 |
|------|------|
| `device_ip` / `host_ip` | 被测端 / 控制端 IP（示例中已脱敏为 `192.168.1.100`） |
| `similarity` / `sim_check` | 图像识别相似度阈值（如 0.8） |
| `rms_speaker` / `rms_mic` | 扬声器 / 麦克风的能量判定阈值 |
| `record_time` | 单次录音时长（秒） |
| `on_off_interval` / `test_interval` | 上下电间隔 / 测试间隔（秒） |
| `switch_mode` | 双系统切换方式（重启切换 / 休眠切换 / 快速切换） |
| `selected_test_items` | 勾选的检测项（扬声器/麦克风/相机/U盘/蓝牙/光感…） |

## 8. 设计亮点小结

- **客观判声**：用频谱能量替代人耳，把"声音正常吗"变成可量化、可回归的布尔判定 —— 这是整套框架最核心的价值。
- **分布式解耦**：控制端与被测端分离，被测端在上下电/切换/休眠过程中断连后能自动重连，控制端有多重超时兜底，保证长时压测不卡死。
- **稳定性打磨**：从版本迭代记录（脚本头部注释）可见，大量精力用于修复"握手死循环、休眠切换失配、模拟器残留进程、中文系统误判"等真实压测坑，是长期真机使用打磨出来的工具。
